## 要件

### REQ-sb-001: 設計スキーマ indexer

`design-doc` スキルが定めたファイル・表ヘッダ・ID だけを読み、`public/snapshot.json` を生成する。`vite build` の前に必ず実行する。テンプレに無い列は必須にしない。`docs/design/` 直下で `manifest.yaml` がある **すべての** `<projectId>` を索引する（ホワイトリストなし・名前非依存）。

ノード / 辺 / details の ID は `{projectId}:{kind}:{localId}` 形式とする。各ノードに `projectId` を載せる。辺種別は `feature→class` / `feature→api` / `class→api` / `class→table` / `class→class`（`inherits`）とする。API のリクエスト/レスポンス JSON とクラスのメソッド表（任意）も details に載せる。

`class→api` は `layers.md` の **関連API** 列に書いた `API-…` のうち、当該機能の `api.md` に存在する ID だけから作る（推測で増やさない）。`feature→api` は機能の `api.md` 一覧から作る。

### REQ-sb-002: ノードキャンバス

ダーク＋ドットグリッド上に **Feature → Class → Api → Table** を左から右へ配置し、曲線でつなぐ。Class 列は **層ごとのサブ列**（例: Domain / UI / API）に分け、縦一本棒にしない。継承辺は破線。パン・ズーム・層フィルタ・関連ハイライト。プロジェクト切替・機能マルチ選択・検索・ギャップのみと併用可能。

UI 層クラスと API 層クラスが同じ Api ノードへ辺を張ることで、**フロントとバックエンドが API で繋がる**関係が見える。

**表示集合が変わったら**、表示中ノードだけを列・サブ列ごとに詰め直して再配置し、ビューポートを fit する（固定座標のまま空を広げない）。

### REQ-sb-003: インスペクタ

選択ノードに応じて REQ・画面ワイヤー・API・責務・カラム・ソースパス・継承元/先に加え、**概要・引数/戻り値・API の JSON 形**を表示する。会話UIではない。関連 CLS / TBL / 機能 / 継承 / API はクリックでノード遷移する（API は詳細内ジャンプまたは一覧選択）。

### REQ-sb-004: GitHub Pages

`develop` への合併後、Actions が build → Pages 公開。Vite `base` は `/HotStreak/`（ローカルは `/`）。`main` は使わない。

### REQ-sb-005: ソース照合とギャップ

`frontend/` `backend/` `src/` を走査（除外: node_modules, target, .git, tools/spec-browser）。CLS-/TBL-/REQ- またはクラス名・テーブル名で照合。ヒットはチェックバッジ、未検出は警告。ギャップ件数をヘッダー表示（選択中プロジェクト分）。

### REQ-sb-006: プロジェクトスコープ（汎用）

ヘッダーで `snapshot.projects` から **常に1つだけ** 選択する（URL `?project=<projectId>`）。プロジェクト固有のハードコード分岐は作らない。

初期値: URL 指定 → なければ一覧の先頭 → 不正 ID なら先頭にフォールバック。

表示・アウトライン・ギャップ件数・検索対象は選択中プロジェクトのみ。他プロジェクトのノード/辺はキャンバスに出さない。新規に `docs/design/<新ID>/manifest.yaml` を置けば、ビューアコード変更なしで切替一覧に載る。

### REQ-sb-007: 左アウトライン（層・種別）

選択中プロジェクト内で次の構成とする。

1. **機能**（チェックでマルチ選択。折りたたみ可）
2. **層ごと**（`layers.md` / クラスの「層」列。例: Domain, UI, API）。配下にクラス。折りたたみ可。見出しは層名をそのまま使う
3. **エンドポイント**（機能の `api.md` の `API-…` 一覧。折りたたみ可）。層名「API」と混同しないよう、このセクション見出しは **エンドポイント** 固定とする
4. **テーブル**（TBL。折りたたみ可）

ノードクリックで選択・インスペクタ・キャンバスハイライト・`?node=` を更新する（エンドポイントも Api ノードとしてキャンバス上に存在し、選択・フィットできる）。セクションは開閉できる（既定: 機能は開、層/エンドポイント/TBL=開）。

### REQ-sb-008: 機能マルチ選択フィルタ

選択中の機能に属する Feature / Class / Api / Table と、それらを結ぶ辺だけ表示する。0件選択時は **全機能表示**。共通クラスは、選択機能のいずれかが参照していれば表示する。複数機能選択時は、共有クラス経由の横断関係が見えること。表示集合変更時は REQ-sb-002 の再配置を行う。

### REQ-sb-009: 検索・ギャップのみ

ラベル / CLS- / TBL- / 機能ID / API-ID の部分一致でアウトラインとキャンバスを絞る。「ギャップのみ」で `implemented === false` に限定する。表示集合変更時は再配置。

### REQ-sb-010: 継承辺（任意）

クラス表の任意列 **`継承元`**（値は `CLS-…`、無し可）だけから Class→Class 辺（種別 `inherits`、破線）を作る。列欠落は継承なしと同じ。インスペクタに継承元/先を出し、クリックでジャンプする。

### REQ-sb-011: モバイル（狭幅）最適化

ブレークポイント: ビューポート幅 **≤768px** をモバイルとする。

- デスクトップ: 三ペイン（アウトライン | キャンバス | インスペクタ）
- モバイル: キャンバス全幅を主面。アウトライン／インスペクタはドロワーまたはボトムシート（同時に両方は開かない）
- ヘッダーは折りたたみ可能。プロジェクト切替・検索・ギャップは到達可能
- タッチ: パン／ズームは React Flow、ノードはタップで選択。コントロール余白は指向け
- 空状態・エラーも狭幅で読めること

### REQ-sb-012: 表示集合のコンパクト再配置

機能フィルタ・検索・ギャップのみ・層フィルタ・プロジェクト切替のあと、**今見えているノードだけ**を次の帯で詰め直す。

1. Feature 列
2. Class 帯（層サブ列。既定順: Domain → UI → API → その他は名前順。空サブ列は潰す）
3. Api 列（エンドポイント）
4. Table 列

ノード間の縦間隔は一定。完了後に fitView。手で動かした位置は保持しない。

### REQ-sb-013: データ形（概要＋JSON / メソッド）

設計書に任意で書けるデータ形を indexer が読み、インスペクタに出す。

- **API**: 一覧表の概要・主な入出力に加え、各 API 節のリクエスト/レスポンス JSON（任意）。無い場合は表の文言のみ
- **クラス**: 責務（概要）に加え、メソッド表（メソッド / 引数 / 戻り値 / 概要）を任意で載せる。列欠落・節欠落は「未記載」
- 言語固有の型定義や実装コードは書かない。概念的な JSON と自然言語の形でよい

### REQ-sb-014: コンパクト・ミニマップ

デスクトップのみ MiniMap を出す（モバイルは出さない）。サイズは小さめ（おおよそ幅 120px・高さ 90px 前後）で右下に置き、キャンバス本体の視認を妨げない。パン／ズーム操作は既存どおり。
