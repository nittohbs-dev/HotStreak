# スマホ画面

会場アプリ `./play.sh --windowed` を起動し、画面のQRをスマホで読み取って参加します。
会場PCと同じWi-Fiを使用してください。Phoneの配信とREST/WSは同じサーバー・オリジンです。

## 実プレイの流れ

ロビー → 公開カード待機 → マ券選択 → カード仕込み → レース観戦 → 配当。
配当後は次のマ券選択へ戻り、第3レースの後は新しい受付へ戻ります。
画面移動は `live-connection.js` がサーバーの現在フェーズに合わせて行います。

- `lobby.html`: QR参加・名前確定・参加者一覧。全員が参加してから名前を確定してください。
- `betting.html`: 自分の手番で山を選び、セーフ／リスキーを確定。第3レースは1枚だけダブル指定。
- `card-seed.html`: 手札3枚のうち1枚を仕込み。確定後は変更できません。
- `race.html`: 現在順位、自分の札、全員の所持金・札を確認。
- `payout.html`: 実際の着順・本人の精算内訳・所持金順位・共同優勝。

HTML/CSS/JavaScriptのみで動き、ビルドは不要です。
画面デザイン、状態検証、描画は既存の `*-state.js` / `*-view.js` を使います。

## 通信契約

`GET /api/sessions/{sid}` で現在フェーズとスナップショットを取得し、`WS /ws/sessions/{sid}` の通知で更新します。
WSを先に接続し、接続時にもGETで最新状態を取得するため、切断中のフェーズ遷移にも追いつけます。

参加時のHttpOnly Cookieが本人認証です。URLのplayerIdだけでは他人を操作できません。
マ券・ダブル・仕込みには操作IDを付けます。応答だけが失われた際の再送にも同じIDを使い、二重に処理しません。
仕込みのWSは進捗のみ。手札と仕込んだ札は認証済みの本人のGETで取得します。
手札操作の `handCardId` はカード絵柄のIDではなく物理カードの個体IDです。同じ絵柄が複数枚あっても区別できます。

ロビーを再読み込みすると設計どおり新規参加になります。通信再接続だけの場合は再参加しません。

## デモ

実セッションを指定しないカード仕込み・レース・配当の単独HTMLは、従来の表示用モックです。
ロビーとマ券は `?demo=1` を付けるとデモが動きます。ゲームを遊ぶ場合は会場QRから参加してください。

`lobby-connection.js` / `betting-connection.js` は旧単独画面向けの接続アダプタです。
現行アプリは `live-connection.js` を使います。

## 検証

```sh
node --test tests/hotstreak_phone/*.test.js
```

状態検証、描画、デモ操作に加え、実接続のフェーズ復帰と、応答消失後の操作ID維持を検証します。
サーバー側の3レース結合テストは `tests/hotstreak_core/test_playable_game.py` です。
