# 機能設計: 設計把握キャンバス

## ユースケース

| UC-ID | 操作者 | やりたいこと | 結果 |
|-------|--------|--------------|------|
| UC-sb-001 | SE/PG | 設計の関係を図で把握する | キャンバスに機能・クラス・テーブルが並ぶ |
| UC-sb-002 | SE/PG | ノードの詳細を見る | 右インスペクタに設計とソース有無が出る |
| UC-sb-003 | SE/PG | 実装ギャップを知る | ヘッダーに件数、未ヒットはバッジで分かる |
| UC-sb-004 | SE/PG | Pages で共有する | 静的サイトが開ける |

## ビジネスルール

| BR-ID | ルール | 例外時の振る舞い |
|-------|--------|------------------|
| BR-sb-001 | 辺は設計表に書いた CLS/TBL だけ。推測で増やさない | 表に無い参照は無視 |
| BR-sb-002 | ノードの新規作成・辺の手編集はしない | UI に編集ハンドルを出さない |
| BR-sb-003 | ソース全文を snapshot に入れない | パスと ID ヒットのみ |
| BR-sb-004 | 設計ゼロでもキャンバスは開く | プレースホルダ1ノード |

## 要件

### REQ-sb-001: 設計スキーマ indexer

`design-doc` スキルが定めたファイル・表ヘッダ・ID だけを読み、`public/snapshot.json` を生成する。`vite build` の前に必ず実行する。テンプレに無い列は必須にしない。

### REQ-sb-002: ノードキャンバス

ダーク＋ドットグリッド上に Feature / ClassCommon / ClassFeature / Table を左から右へ配置し、曲線でつなぐ。パン・ズーム・層フィルタ（表示切替）・関連ハイライト。

### REQ-sb-003: 右インスペクタ

選択ノードに応じて REQ・画面ワイヤー・API・責務・カラム・ソースパスを表示する。会話UIではない。

### REQ-sb-004: GitHub Pages

`develop` への合併後、Actions が build → Pages 公開。Vite `base` は `/HotStreak/`（ローカルは `/`）。`main` は使わない。

### REQ-sb-005: ソース照合とギャップ

`frontend/` `backend/` `src/` を走査（除外: node_modules, target, .git, tools/spec-browser）。CLS-/TBL-/REQ- またはクラス名・テーブル名で照合。ヒットはチェックバッジ、未検出は警告。ギャップ件数をヘッダー表示。
