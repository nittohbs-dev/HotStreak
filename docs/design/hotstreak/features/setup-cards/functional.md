# 機能設計: 公開カード準備

## ユースケース

| UC-ID | 操作者 | やりたいこと | 結果 |
|-------|--------|--------------|------|
| UC-setup-001 | システム | lobby 完了後に公開カードと手札を配る | 公開カード集合と各手札3枚が確定する |
| UC-setup-002 | 司会（Display） | 公開カードを会場に見せる | SCR-display-002 に表向きカードが表示される |
| UC-setup-003 | プレイヤー | （操作なし）気配を見てベット判断の材料にする | Phone は待機。手札は次フェーズ以降で参照 |

## ビジネスルール

| BR-ID | ルール | 例外時の振る舞い |
|-------|--------|------------------|
| BR-setup-001 | フェーズ遷移にタイマーを使わない | Enter のみ（本フェーズにプレイヤー操作の全員揃いは無い） |
| BR-setup-002 | スターターはマスコット4体各1枚を表向きに含める | 欠ける場合は配布失敗として再抽選 |
| BR-setup-003 | 追加のランダム公開枚数は人数表に従う | 下表。総公開＝4＋追加 |
| BR-setup-004 | 各プレイヤーへ初期手札3枚を配る | lobby では所持金のみ。手札は本機能で付与 |
| BR-setup-005 | 公開カードと手札は同一のレースカード供給から重複なく取る | 同一 cardInstance を二重配布しない |
| BR-setup-006 | 公開枚数＋参加者数（各1枚仕込み）＝18 を満たす | 3人:15公開、8人:10公開。card-seed で検証 |
| BR-setup-007 | setup-cards では Phone 専用操作画面を出さない | Display のみ。Phone は待機／次フェーズ待ち |

## 要件

### REQ-setup-001: 自動配布

フェーズが `setup-cards` に入った直後、Sync が公開カード抽選と手札配布を一度実行する。再入場や二重配布はしない。

### REQ-setup-002: スターター4枚

公開カードにはマスコット Gobbler / Hurley / Dangle / Mum（表示名はアセットに合わせる）各1枚のスターターを必ず含める。

### REQ-setup-003: 人数別追加枚数

参加者数に応じて上表の追加ランダム枚数を供給山から表向きに出す。総公開＝4＋追加。

### REQ-setup-004: 初期手札

各 Player に race カードを3枚配る。手札は Phone の card-seed／betting 以降で参照する（本フェーズでは選択 UI なし）。

### REQ-setup-005: Display 同期

配布完了後、全接続クライアントへ `setup.state` を push する。Display は SCR-display-002 で公開カードを描画する。

### REQ-setup-006: Enter で betting へ

Display からの advance（ラズパイ Enter）でフェーズを `setup-cards` から `betting` に遷移し、`setup.advanced` を配信する。

### REQ-setup-007: 18枚前提

総公開枚数が「18 − 参加人数」であること（上表）。card-seed 設計で山枚数を再確認する。
