# 機能設計: 参加・ロビー

## ユースケース

| UC-ID | 操作者 | やりたいこと | 結果 |
|-------|--------|--------------|------|
| UC-lobby-001 | プレイヤー | QR を読み取って試合に参加する | playerId が発行されロビー画面が開く |
| UC-lobby-002 | プレイヤー | 表示名を入力して確定する | 参加者一覧に反映され初期 $10 が付与される |
| UC-lobby-003 | 司会（Display） | 参加者状況を会場に共有する | QR と参加者一覧が更新表示される |
| UC-lobby-004 | 司会（Display） | Enter でセットアップを完了する | 未確定名はプレースホルダ化され setup-cards へ進む |
| UC-lobby-005 | システム | 全員の名前が揃ったら進行可能にする | 全員揃いでも setup-cards へ進める |

## ビジネスルール

| BR-ID | ルール | 例外時の振る舞い |
|-------|--------|------------------|
| BR-lobby-001 | フェーズ遷移にタイマーを使わない | 全員揃いまたは Enter のみ |
| BR-lobby-002 | 参加者は 3〜8 人（標準人数） | 9人目以降の参加は拒否 |
| BR-lobby-003 | 名前確定時に初期所持金は $10 | 再確定では所持金を増減しない |
| BR-lobby-004 | 初期手札 3 枚は setup-cards で付与する | lobby では所持金のみ初期化 |
| BR-lobby-005 | Enter 時、名前未確定のプレイヤーは `プレイヤーN`（参加順）で確定 | N はセッション内で一意 |
| BR-lobby-006 | lobby 完了後は新規 join を拒否 | HTTP 409 相当 |
| BR-lobby-007 | advance には最低 3 人の参加者が必要 | 3人未満は Enter 不可（全員揃いも同様） |

## 要件

### REQ-lobby-001: セッションと QR

Display 起動時に Sync へセッション作成を依頼し、参加用 URL（QR コード化）を SCR-display-001 に表示する。URL はセッション ID を含む。

### REQ-lobby-002: QR 参加

Phone が QR の URL を開き join API を呼ぶ。成功時に playerId と現在のロビー状態を返す。同一端末の再読込は新規 player として扱う（再参加・復帰はスコープ外）。

### REQ-lobby-003: 名前確定と同期

プレイヤーが非空の表示名を確定すると、全接続クライアントへ参加者一覧が push される（WebSocket `lobby.state`）。Display の人数・リストも同期更新する。

### REQ-lobby-004: 初期所持金

名前確定時に Player の所持金を $10 に設定する。既に確定済みのプレイヤーが名前を変更した場合は所持金を変えない（lobby では名前変更 API は提供しない）。

### REQ-lobby-005: 人数制限

ロビー中の参加者数は 3〜8 人。上限超過の join は拒否する。advance 時点で 3 人未満の場合は進行を拒否する。

### REQ-lobby-006: フェーズ遷移

全員の名前が確定した状態（全員揃い）、または Display からの Enter（advance API）で、ゲームフェーズを `lobby` から `setup-cards` に遷移する。

### REQ-lobby-007: Enter 時のプレースホルダ名

advance 実行時、名前未確定のプレイヤーがいれば参加順に `プレイヤー1` … を付与して確定扱いにする。その後 $10 付与（未付与分のみ）し、setup-cards へ進む。

### REQ-lobby-008: 受付停止

フェーズが `setup-cards` 以降になったら join API は拒否し、ロビー画面は次機能の画面へ遷移する。
